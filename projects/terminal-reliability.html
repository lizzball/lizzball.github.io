THE CENTRAL QUESTION

Start with the question.

If a model can identify a terminal at risk of failure, when should a support team intervene — and which trade-offs are acceptable?

A useful model begins with a defensible scientific question.
PROVENANCE & SAMPLING

Know the data.

The project generates 4,000 synthetic terminals observed across 30 days. The README describes 24,000 held-out terminal-day prediction observations and a 2.67% positive rate within that evaluation set. There are no internal Block or Square customer records.

WORKFLOW

Make the methods visible.

  • Construct snapshot and longitudinal telemetry features using leakage-safe historical windows.
  • Compare logistic regression and XGBoost with grouped holdout validation by terminal.
  • Evaluate precision and recall as well as ranking metrics for a low-prevalence event.
  • Model how different decision thresholds alter the number of interventions, misses and unnecessary touches.
WHY IT MATTERS

What it means.

Predictive ranking is only the first step. Actionability depends on prevalence, intervention costs, false positives, missed failures and the operational context.

BOUNDARIES OF EVIDENCE

What it does not mean.

  • All telemetry is synthetic and is not representative of a real commercial system.
  • Threshold examples are scenario analysis, not measured business outcomes.
  • Generalization would require real-world, properly permissioned validation.
