Synthetic Diagnostic Laboratory

An approachable relational SQL learning environment built around the shape of real diagnostic workflows, without real patient records.

THE CENTRAL QUESTION

Start with the question.

How can a realistic but entirely synthetic laboratory schema help demonstrate relational querying and the difference between imperfect biomarker signal and classification?

A useful model begins with a defensible scientific question.
PROVENANCE & SAMPLING

Know the data.

Three related tables represent synthetic patients, ordering providers and lab tests. The laboratory data are purpose-built for teaching; biomarker A contains an intentionally imperfect association with case status, while the other features overlap substantially.

1,000synthetic patients
1,000lab tests
12ordering physicians
WORKFLOW

Make the methods visible.

  • Build a consistent relational structure using patient and ordering-provider keys.
  • Practice SQL selection, filtering, aggregation, joins, grouping and case logic.
  • Explore diagnostic-style thresholds with overlapping synthetic biomarkers.
  • Use a repeatable local setup through GitHub Codespaces or SQLite.
WHY IT MATTERS

What it means.

This is a teaching and data-skills project, not a clinical dataset. Its value lies in transparent assumptions and examples that expose the difference between tables, measurements and decisions.

BOUNDARIES OF EVIDENCE

What it does not mean.

  • No rows describe actual patients or healthcare providers.
  • Simulated distributions should not be interpreted as epidemiological findings.
